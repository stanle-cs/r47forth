Stage 2 of the Forth package is done.

Stage 1 accepted one line at a time. Alpha-enter a line so it lands in X as a
string, then XEQ FORTH. That still works. Forth source can now be part of a
normal R47 program, stored as program steps.

In PEM you insert FORTH and an alpha editor opens on the source. The closing
marker goes in at the same time and the region stays balanced from the start.
ENTER stores the line and opens the next one inside the pair, EXIT closes the
editor, and EDIT reopens a line later.

[code]: SQ2 DUP × ;
: TWICE DUP + ; GLOBAL[/code]

SQ2 is private to the program it sits in. TWICE has GLOBAL after it. That moves
it to the global dictionary, where it survives power-off and backup/restore and
can be called from the keyboard. I made program-local the default because two
programs that both define SQ2 shouldn't be able to break each other.
Definitions get scanned before the program runs, so a word can be used above
the line that defines it.

Control flow from source is IF/ELSE/THEN, BEGIN/UNTIL, BEGIN/AGAIN and
BEGIN/WHILE/REPEAT. RECURSE, IMMEDIATE and FORGET are also in.

Forth can call C47 functions with the normal parameter forms: direct numbers
and registers, named registers, flags, and the indirect forms. It goes through
the same validation and dispatch code the keyboard uses. There's no second copy
to drift out of step. XEQ resolves C47 labels, C47 functions and Forth words,
and R47 programs can XEQ Forth words back. FWRD lists the words the current
program can see, and picking one inserts it at the cursor.

A source line gets checked before it is stored. Structure and parameter forms
only. Nothing touches the dictionary, and a bad line leaves the original
program step alone.

Where Forth convention and R47 convention disagree, R47 wins. Forth extends
the programming system that's already there.

[b]Sample program[/b]

Two normal R47 programs. FDEMO is the main one; NATADD is a global label called
from Forth. Use the calculator's right-arrow glyph. The two ASCII characters
-> won't work.

[code]LBL 'FDEMO'
»FORTH
: SUMDOWN DUP IF DUP 1 - RECURSE + THEN ;
: COUNTDOWN BEGIN DUP WHILE 1 - REPEAT ;
: UNTIL1 BEGIN 1 - DUP UNTIL DROP ;
: CHOOSE IF 111 ELSE 222 THEN ;
: SPIN BEGIN AGAIN ;
: PLUS10 10 + ; GLOBAL
: GONE1 1 ; GLOBAL
: GONE2 2 ; GLOBAL
: IMM3 3 ; IMMEDIATE
: EMPTY IMM3 ;
: CALLWORD XEQ 'PLUS10' ;
: CLEAR XEQ 'CLSTK' ;
CLEAR
5 SUMDOWN STO 00
5 COUNTDOWN STO 01
99 1 UNTIL1 STO 02
1 CHOOSE STO 03
0 CHOOSE STO 04
7 CALLWORD STO 05
42 STO 'DEMO' RCL 'DEMO' STO 06
CNST 10
10 STO 07
SF 10
18 STO 09 77 STO →09 RCL 18 STO 10
19 STO 'PTR' 88 STO →'PTR' RCL 19 STO 11
XEQ :GET0:
STO 12
2
XEQ 'NATADD'
STO 13
5 LATER STO 14
99 EMPTY STO 15
1 2 CLEAR 9 STO 16
FORGET GONE1
: LATER 2 * ;
FORTH«
RTN
LBL :GET0:
RCL 00
RTN
END[/code]

[code]LBL 'NATADD'
»FORTH
100 +
FORTH«
RTN
END[/code]

XEQ 'FDEMO' gives:

[code]R00 = 15   SUMDOWN, IF and RECURSE (5+4+3+2+1)
R01 = 0    COUNTDOWN, BEGIN/WHILE/REPEAT
R02 = 99   UNTIL1, BEGIN/UNTIL, leaves the lower value
R03 = 111  true arm of IF/ELSE/THEN
R04 = 222  false arm of IF/ELSE/THEN
R05 = 17   compiled XEQ of the global Forth word PLUS10
R06 = 42   named variable STO/RCL through 'DEMO'
R07 = 10   execution continued past the direct numeric CNST parameter
R09 = 18   register holding the indirect target number
R10 = 77   STO →09 reached register 18, RCL brought it back
R11 = 88   STO →'PTR' reached register 19 through the named pointer
R12 = 15   XEQ :GET0: called the local R47 label
R13 = 102  XEQ 'NATADD' called the global R47 label
R14 = 10   LATER used before the line that defines it
R15 = 99   IMM3 ran while EMPTY compiled, so EMPTY has no runtime body
R16 = 9    XEQ 'CLSTK' resolved a normal C47 item and cleared the stack[/code]

This wants the 8-level stack. The Forth data stack is the calculator's own RPN
stack. A recursive word holds one operand per level, and SUMDOWN needs about
six. Set to 4 levels it reports a full stack.

Flag 10 ends up set, with DEMO and PTR holding 42 and 19. After a power cycle
PLUS10 is still callable from the keyboard and SUMDOWN isn't, since it belongs
to FDEMO. FORGET GONE1 removes GONE1 and every global defined after it. GONE2
goes with it.

A native C47 item called from Forth doesn't push its result back onto the Forth
stack when the step ends. So R07 checks the literal on the next line. SPIN is
compiled but never run: running it reaches the runaway guard. R/S gets you out
on hardware.

FWRD and the pre-store check don't show up in the registers. To see them, EDIT
one of the Forth lines and open FWRD, then delete THEN from CHOOSE and press
ENTER, which should reject the line and leave the step unchanged.

[b]Compound-interest program[/b]

FDEMO exercises features one at a time. This one is closer to something you'd
actually keep on the machine: it writes a six-period compound interest schedule
into R00 to R05 and leaves the closing balance in R22. GROW is promoted with
GLOBAL and stays on the calculator once the program has finished.

[code]LBL 'SAVE'
»FORTH
: GROW 1.05 * ; GLOBAL
: PUT STO →20 ;
: BUMP RCL 20 1 + STO 20 DROP ;
: TALLY RCL 19 1 - STO 19 DROP ;
: STEP GROW PUT BUMP TALLY ;
: RUN BEGIN RCL 19 WHILE STEP REPEAT ;
0 STO 20 DROP
6 STO 19 DROP
1000 RUN STO 22
FORTH«
RTN
END[/code]

The balance rides the stack the whole way through. R20 is the slot to write
next, R19 the periods left to run, and PUT stores through the indirect form
without popping, so the balance is still there for the next period. XEQ 'SAVE'
gives:

[code]R00 = 1050
R01 = 1102.5
R02 = 1157.625
R03 = 1215.50625
R04 = 1276.2815625
R05 = 1340.095640625
R22 = 1340.095640625[/code]

GROW is still there afterwards. Key 200, then XEQ GROW twice, and you get
220.5. Change the 1.05 for a different rate, or bump the 6 to run the schedule
further up the registers.

RCL now lifts onto a Forth value. Stage 1 overwrote X, so a value couldn't
survive on the stack across RCL. Every dispatch that leaves a value in X now
sets C47's auto-lift flag.

Recursion past the data stack now reports a full stack. With 8 levels and one
operand held per level, a recursive word runs out at 6 or 7. A factorial word
returned 4320 for 7! instead of 5040.

[b]Core dictionary[/b]

[list]
[*][b]DUP[/b] ( x -- x x )
[*][b]DROP[/b] ( x -- )
[*][b]SWAP[/b] ( x y -- y x )
[*][b]OVER[/b] ( x y -- x y x )
[*][b]+[/b] ( x y -- x+y )
[*][b]-[/b] ( x y -- x-y )
[*][b]*[/b] ( x y -- x*y )
[*][b]/[/b] ( x y -- x/y )
[*][b]×[/b] multiplication glyph alias
[*][b]·[/b] multiplication glyph alias
[*][b]÷[/b] division glyph alias
[*][b]: name ... ;[/b] define a word
[*][b]RECURSE[/b] compile a call to the definition being built
[*][b]GLOBAL[/b] promote the last definition completed on this line
[*][b]IMMEDIATE[/b] mark the last definition completed on this line
[*][b]FORGET name[/b] remove a global word and the globals after it
[*][b]XEQ 'NAME'[/b] resolve a global C47 label, C47 function or visible Forth word
[*][b]XEQ :NAME:[/b] resolve a local C47 label
[*][b]IF ELSE THEN[/b] conditional structure, with ELSE optional
[*][b]BEGIN UNTIL[/b] loop until X is true
[*][b]BEGIN AGAIN[/b] unconditional loop
[*][b]BEGIN WHILE REPEAT[/b] loop with a condition in the middle
[/list]

[b]C47 parameter forms[/b]

[list]
[*][b]Direct numeric[/b] CNST 10
[*][b]Direct register[/b] NN, .NN or a register letter
[*][b]Named register[/b] 'NAME'
[*][b]System flag[/b] a flag name from the C47 catalog
[*][b]Indirect register[/b] →nn
[*][b]Indirect named register[/b] →'NAME'
[/list]

[b]Compiled tokens[/b]

[list]
[*][b]0x0000 FTOK_EXIT[/b] end of a colon body
[*][b]0x0001..0x0fff FTOK_PRIM[/b] primitive call
[*][b]0x1000..0x6fff FTOK_CALL[/b] program-local colon call
[*][b]0x7000..0x7eff FTOK_CALL[/b] global colon call
[*][b]0x7f00 FTOK_LIT[/b] real literal
[*][b]0x7f01 FTOK_ILIT[/b] 32-bit integer literal
[*][b]0x7f02 FTOK_BR[/b] unconditional relative branch
[*][b]0x7f03 FTOK_0BR[/b] branch when X is zero
[*][b]0x7f04 FTOK_C47[/b] C47 item and its inline parameter
[*][b]0x7f05 FTOK_XEQN[/b] XEQ name and label kind
[/list]

[b]Source-name precedence[/b]

[list]
[*] Forth primitive
[*] Visible Forth definition, current program first and globals second
[*] Number
[*] C47 function
[*] Global C47 label
[/list]

XEQ has the calculator's existing order: C47 label, C47 function, then a
visible Forth definition. R47 programs also fall through to visible Forth
words.

[b]Limits[/b]

[list]
[*] Return stack: 64 calls
[*] Runaway guard: 4096 dispatches
[*] Source buffer: 256 bytes
[*] Word name: 31 characters
[*] Token: 63 characters
[*] Nested inner interpreters: 4
[*] Data stack: the calculator's 4- or 8-level stack
[/list]

Stage 1 printed 63 as the name limit. That was the token limit. Names stop at
31.

IF checks X for zero. Any non-numeric type counts as true. A string or matrix
takes the true branch.

[b]Current language limits[/b]

CREATE/DOES>, VARIABLE, CONSTANT, vocabularies, and a separate Forth terminal.
Source is stored as R47 program steps and the C47 catalog supplies most of the
functions. This still isn't a complete ANS Forth.

Everything you need is on a
[url=https://github.com/stanle-cs/r47forth/tree/release/forth-core-stage2]release
branch[/url]: the package system, the package itself as 14 diffs plus 13 new
sources, and install notes. It's the bare build tree, generated against
upstream c43 b8f79e486. Clone upstream at that commit, copy the files over,
then:

[code]make dist_dmcp5r47 CUSTOM_PKG=packages/forth-core[/code]

forth-core needs the custom package v0.3 resolver. Target is R47/C47 on the
DM42n under DMCP5. Building without CUSTOM_PKG gives you the stock firmware.

The code is GPL-3.0-only. The release branch and forth-core.zip carry COPYING.

Tested on the simulator and on my R47. This is a hobby project modifying
calculator firmware. Keep a backup of your state and flash at your own risk.
