Custom package v0.5 is ready. The package manager lets you build C47 and R47 firmware with your own features layered cleanly on top, without modifying anything under src/. If you leave CUSTOM_PKG unset, the build produces the exact stock firmware byte for byte.

This update brings automated upstream folding for Merge Requests, isolated integration sessions that never touch your working tree, package auditing, and support for test suite patches.

[b]Commands[/b]

All package operations run through the ./package entry point:

[list]
[*]refresh: scans your package's working area, diffs your edited files against upstream at your package's recorded base commit, and generates patches/ and files/. The compiler only builds from these generated patches, so run this whenever you edit your working code.
[*]materialize: pulls an upstream file into your package at its recorded base commit. If you just copied a file out of your working tree, upstream commits would get baked into your patch as if they were your changes. Materialize makes sure your diff contains only what you actually edited.
[*]status: checks if your package is locally buildable or if upstream moved. It reports whether your base commit matches upstream HEAD, checks for dirty working files, and flags conflict markers before you start compiling.
[*]build: refreshes patches, reconfigures Meson, and runs Ninja in one step. It saves you from typing separate commands during quick edit-build loops.
[*]rebase: advances your package's base commit when upstream moves forward. It updates your base commit and re-applies your working edits onto the new code.
[*]integrate: runs a full integration session against a new upstream commit in an isolated worktree. Direct rebasing in your main tree can cause problems if a merge conflict occurs. Integrate works in a separate directory under .package-sessions/ without touching your active tree or uncommitted files. If a conflict occurs, it pauses and gives you the exact paths to resolve.
[*]resume: continues a paused integration session after you resolve a merge conflict or fix a build error. It saves your progress so you do not have to restart the session from the beginning.
[*]audit: checks your package for line-count budgets, whitespace churn, allocation lifetimes, and manifest hash integrity before distribution. Embedded hardware has strict memory limits, so this catches footprint creep early.
[*]upstream: folds one or more packages into a clean upstream branch, registers new C files in src/c47/meson.build, runs the native upstream test suite, and can push to GitLab and open a Merge Request automatically. Upstream maintainers require commits directly against src/, so this command handles the tree conversion and registers your sources automatically.
[/list]

[b]How packages work[/b]

A package is a flat directory under packages/ mirroring upstream paths:

[code]
packages/my-pkg/
    keyboard.c                  edited copy of an existing upstream file
    my_feature.c                new source file with no upstream counterpart
    testSuite/my_tests.c        new test file under a sibling root
    .pkgignore                  files to exclude from distribution
[/code]

Running ./package refresh my-pkg classifies your files automatically:
[list]
[*]Files matching an upstream path become diffs in patches/, such as 010-keyboard.c.patch.
[*]Brand new files get copied verbatim into files/.
[*]Test drivers under testSuite/ map to src/testSuite/ through sibling roots, so you can add tests without touching production firmware files.
[*]Files matching .pkgignore (like README.md or build scripts) stay out of the generated package payload.
[/list]

[b]Building and testing[/b]

To build the simulator with your package active:
[code]make sim CUSTOM_PKG=packages/my-pkg[/code]

You can load multiple packages together by passing a comma-separated list:
[code]make sim CUSTOM_PKG=packages/forth-core,packages/undo-history,packages/pretty-print,packages/program-graphics[/code]

When multiple packages patch the same file, the resolver applies their patches in numerical filename order (005 before 010). If two patches touch different parts of the same function, git apply -3 merges them cleanly. If they collide on the exact same lines, configure stops and shows you which patch failed.

For hardware, build with your target:
[code]make dist_dmcp5r47 CUSTOM_PKG=packages/my-pkg[/code]

To run the firmware test battery with your package active:
[code]make test CUSTOM_PKG=packages/my-pkg[/code]

And to build a clean distribution zip:
[code]make pkg_build PKG=packages/my-pkg[/code]
This cleans, runs the test suite with the package active, refreshes patches, verifies the archive size, and outputs pkg_dist/<package>.zip with COPYING included.

[b]Download and install[/b]

The package manager archive is c47-pkg-manager-v0.5.zip. It contains the integration patch, the ./package tool, the Python scripts, and the test suite.

Before applying anything, run the unit test suite to verify the tooling:
[code]
python3 tools/test_pkg_patch_common.py
python3 tools/test_pkg_patch_refresh.py
python3 tools/test_pkg_patch_resolver.py
python3 tools/test_pkg_patch_integrate.py
python3 tools/test_pkg_patch_upstream.py
python3 tools/test_custom_pkg_make_reconfigure.py
[/code]
All 204 checks run independently of an upstream tree.

To install:
[code]
git clone https://gitlab.com/rpncalculators/c43.git
cd c43
git checkout 00.109.04.00b0
git apply pkg-manager-integration.patch
[/code]

The patch targets upstream c43 release 00.109.04.00b0 (commit 057b62fc0). Everything is licensed under GPL-3.0-only.

Four packages currently use this system:
[list]
[*]forth-core: interactive Forth environment and REPL
[*]undo-history: multi-level undo stack and history browser
[*]pretty-print: 2D natural display for stack values and equations
[*]program-graphics: 2D drawing canvas and interactive 3D wireframes
[/list]
Full reference and architecture notes are in design-docs/package-manager/README.md.
