# Program graphics: plan, version 2

Date: 2026-09-04. Status: plan after Stan's rulings of the same day.
Companion: `SURVEY_program-drawing_2026-09-04.md` (the facts about the code)
and `RESEARCH_hp-conventions_2026-09-04.md` (the facts about HP commands).
Package name: `program-graphics`. Implementer: Claude directly, no local model.

## 1. Goal

A user program draws on the screen. The drawing stays on the screen when the
program stops. The program can draw 3D wireframes. The drawing must be as
fast as the calculator allows. The package follows the package system:
working area under `packages/program-graphics/`, patches and files from the
refresh tool, gate green alone and with the other packages, audit rounds,
then one merge request to upstream.

## 2. Rulings of 2026-09-04

| Decision | Ruling |
|---|---|
| 1. How a drawing stays after STOP | A canvas view. The canvas is the register region only, or the register region plus the softmenu region. The status bar always stays live. Both sizes are supported. The upstream flag protocol (option B) stays usable without the view. |
| 2. How a command gets its points | From the stack. The command does not remove them. |
| 3. 2D commands | Content accepted. Names must follow an HP convention. See section 4. |
| 4. Where the commands live | A new menu at the tail of the menu table, plus the FCNS catalog. |
| 5. 3D scope | Wireframe only. Names must make sense. See section 5. |
| 6. Window with real coordinates | Yes. |
| 7. Who writes the code | Claude, directly. |
| 8. Package name | program-graphics. |
| Core requirement | Speed. The drawing must be as instantaneous as possible. See section 6. |

## 3. The canvas view

### 3.1 Regions

The screen has three regions. The rows come from `defines.h:1518-1524`.

| Region | Rows | HP-48 FREEZE code |
|---|---|---|
| Status bar | 0 to 19 | 1 |
| Register lines (T, Z, Y, X) | 20 to 170 | 2 |
| Softmenu (three rows of 23 pixels) | 171 to 239 | 4 |

The HP-48 command `FREEZE n` stops the update of the regions whose codes
add up to n. The canvas view uses the same codes. `PVIEW 2` opens a canvas
over the register lines. `PVIEW 6` opens a canvas over the register lines
and the softmenu. The status bar stays live in both. Code 1 is not
supported in the first version.

### 3.2 Behaviour

| Event | Behaviour |
|---|---|
| `PVIEW n` runs | The calculator enters mode 21 (the free value in the package registry 19 to 23). The canvas region is cleared. The softmenu is cleared when n includes 4. |
| A drawing command runs, view open or closed | The command writes the frame buffer. It does not repaint anything else. |
| A drawing command runs, view closed | The upstream flag protocol applies, as for PIXEL today. The drawing lives until the next repaint. |
| The program stops in the view | The stop path sees mode 21 and does not repaint the canvas. The drawing stays. |
| R/S in the view | The program continues. The canvas stays. |
| EXIT in the view | The view closes. The previous mode returns. The calculator repaints the normal screen. |
| Any other key in the view | Ignored, on both key paths (direct keys and softkeys). |
| Sleep or power off | Upstream repaints on wake. The drawing is lost. The program must draw again. Documented limit. |

The canvas is the frame buffer. The package keeps no copy of the screen. The
package RAM is a few bytes of state: the mode to return to, the region code,
the clip rectangle, the draw mode, and the window ranges.

## 4. The 2D commands

### 4.1 Naming lineage

C47 is in the HP-42S line. Upstream already has the HP-42S graphics words
`CLLCD`, `PIXEL`, `AGRAPH`, and `CLD`. Plus42, the extended Free42, adds
`LINE`. The RPL line (HP-48, 49, 50) has the largest vocabulary: `PIXON`,
`PIXOFF`, `LINE`, `TLINE`, `BOX`, `ARC`, `ERASE`, `PVIEW`, `FREEZE`,
`XRNG`, `YRNG`, `PX→C`, `C→PX`, `DRAX`, `LABEL`. The HP Prime uses the same
words with a `_P` suffix for pixel coordinates, plus `RECT`, `FILLPOLY`,
`TEXTOUT`, and `INVERT`. The rule for this package: use the Plus42 word when
one exists, then the RPL word, then the Prime word. A word without any HP
precedent is marked.

Item names can hold 15 bytes (`typeDefinitions.h:606-607`). A softkey shows
about seven characters without compression.

### 4.2 Point order on the stack

Plus42 `LINE` reads x1 from X, y1 from Y, x2 from Z, and y2 from T. It also
accepts two complex numbers, x1+iy1 in X and x2+iy2 in Y. The package uses
the same order. This replaces the T,Z to Y,X order of the first plan draft.
One-point commands read x from X and y from Y, as `PIXEL` does.

### 4.3 Pixel or user coordinates

RPL selects the coordinate kind by the argument type. A binary integer is a
pixel. A complex number is a user coordinate. C47 makes the same split with
no new syntax: a long integer is a pixel, a real is a user coordinate. The
user coordinates come from `XRNG` and `YRNG`. The default window is the
pixel grid, so a real behaves as a pixel until `XRNG` or `YRNG` change the
window. A complex number counts as two reals. The long integer path skips
the window transform, so it is the fast path. Pixel coordinates keep the
upstream convention: origin bottom left, x 0 to 399, y 0 to 239. This point
needs Stan's confirmation. It merges decisions 2 and 6.

### 4.4 The commands

| Command | Reads | Draws | Precedent |
|---|---|---|---|
| `PVIEW n` | parameter n = 2 or 6 | Opens the canvas view over the region. | RPL `PVIEW` plus `FREEZE` codes |
| `ERASE` | nothing | Clears the canvas region. Opens the view when closed. | RPL `ERASE` |
| `LINE` | X,Y to Z,T | Line. | Plus42 `LINE`, RPL `LINE` |
| `BOX` | X,Y to Z,T | Rectangle outline. | RPL `BOX` |
| `RECT` | X,Y to Z,T | Filled rectangle. | Prime `RECT`, which fills by default. |
| `ARC` | center as a complex number in T; radius in Z; start angle in Y; end angle in X | Arc, counterclockwise. A full circle when the span is 360 degrees or more. | RPL `ARC`, which also takes the center as one object |
| `CIRCLE` | center x in X, y in Y; radius in Z | Circle outline. A short form of `ARC` with a real center. | none. Prime `ARC` with no angles. |
| `FCIRCL` | center x in X, y in Y; radius in Z | Filled circle. | none |
| `TEXTOUT` | X,Y and the alpha register | Text at a position, standard font. | Prime `TEXTOUT` |
| `GMODE n` | parameter n = 0, 1, 2 | Set, clear, or invert, for all commands. | RPL `TLINE` for invert, 42S `GRAMOD` |
| `GCLIP` | X,Y to Z,T | Clip rectangle for later commands. `ERASE` resets it. | none |
| `XRNG` | X,Y | x range of the user coordinates. | RPL `XRNG` |
| `YRNG` | X,Y | y range of the user coordinates. | RPL `YRNG` |

`ARC` needs five values: center x, center y, radius, and two angles. The
stack has four levels. RPL solves this with the center as one object. The
package does the same: the center is a complex number in T. `CIRCLE` covers
the common case with a real center in X and Y. `PIXEL`, `POINT`, `AGRAPH`,
and `CLLCD` do not change. `TLINE` is not added because `GMODE 2` covers it.

## 5. The 3D commands

RPL draws 3D plots through the plot type `WIREFRAME`. The view comes from
`EYEPT` (the eye point), `XVOL`, `YVOL`, `ZVOL` (the view volume), and
`NUMX`, `NUMY` (the grid counts). The package uses the same words.

| Command | Reads | Effect | Precedent |
|---|---|---|---|
| `EYEPT` | x in Z, y in Y, z in X | Sets the eye point. | RPL `EYEPT` |
| `XVOL`, `YVOL`, `ZVOL` | low in Y, high in X | Set the view volume. | RPL |
| `NUMX`, `NUMY` | X | Set the grid counts. | RPL |
| `WIREFRAME` | the label of the user program | Runs the program at each grid point of z = f(x, y). Joins the adjacent points with lines. | RPL `WIREFRAME` |
| `PT3D` | x in Z, y in Y, z in X | Sets the current 3D point. No precedent. |
| `LINE3D` | x in Z, y in Y, z in X | Draws a 3D line from the current point to this point. This point becomes the current point. No precedent. |

Perspective comes from the eye point, as in RPL. A separate orthographic
flag is not in the first version. `WIREFRAME` keeps two rows of projected
points at a time, so it uses a few hundred bytes of the transient pool.

The 3D math runs in float. The processor of the DM42 has hardware for
float only. Double math runs in software and is slow. The float sine and
cosine come from the C math library. Upstream removed the double pow, exp,
log, and sqrt from the link to save flash (e989d752b). The flash cost of the
float functions is measured in G4 before the stage is accepted. The fallback
is a small sine table in flash.

## 6. The speed law

### 6.1 What one program step costs today

A verified reading of the interpreter path gives these per-step costs while
a program runs. None of them is the pixel write.

| Work | Where | Cost | Can the package skip it? |
|---|---|---|---|
| Six timer stops through `resetKeytimers` | `items.c:287`; `timer.c:72-86` | About 66 timer-slot reads per step on the DM42. | No. Only CLX skips it. |
| Status bar repaint | `items.c:399` | Full bar walk every 256 steps. | No. |
| Conversion-item binary search | `items.c:571` | log2 of the table per step. | No. |
| Battery sample | `items.c:612` | One clock read per step, an ADC read on a schedule. | No. |
| Key poll | `lblGtoXeq.c:961-972` | One clock read per step, a key probe every 128 ms. | No. |
| Undo snapshot | `items.c:294` | Skipped while a program runs, unless flag IGN1ER is set. Copies the whole stack when it runs. | Yes. `US_UNCHANGED` skips it always. |
| Stack lift flag write | `items.c:604-609` | One flag write. | Yes. `SLS_UNCHANGED`. |
| Register to integer conversion in `PIXEL` | `screen.c:6458-6513` | Two decimal compares, one decimal to number, one to int32, per register. Twice per call. | Yes. The package owns its bodies and converts its own way. |

### 6.2 When the LCD is refreshed today

On the DM42, nothing refreshes the LCD between program steps
(`lblGtoXeq.c:955-993`; `items.c:356-364`). A drawing appears only at
PAUSE, at a program stop, at SNAP, or when a key waits with the monitor
flag set. On the simulator, a timed refresh runs about once a second, and
only with the monitor flag set (`items.c:362`; `screen.c:1830-1858`). So
today a program that draws 1,000 pixels shows nothing until it stops.

### 6.3 The laws

1. A drawing command converts its arguments with one fast path per type: a
   long integer reads the low word directly, a real converts with one
   decimal to int32 call. No decimal compares.
2. A drawing command is `US_UNCHANGED` and `SLS_UNCHANGED`. It never saves
   an undo state and never touches the stack lift flag.
3. A drawing command writes the frame buffer with integer math only. Lines
   use the integer stepper. Horizontal runs use the rectangle fill.
4. The package owns the LCD refresh. Each drawing command reads the clock
   once. When more than 40 ms passed since the last flush, it flushes the
   dirty rows with the DMA refresh (`dmcp.h:95`) and does not wait. PAUSE,
   STOP, PVIEW, and EXIT flush at once.
5. The stage G0 measures a baseline: PIXEL steps per second on the
   simulator and on the DM42, with a 1,000-step program and `TICKS`. Every
   later stage reports the same number for LINE and for WIREFRAME. A
   drawing command must cost less than the interpreter's own per-step work.

Every stage ends with: gate green for the package alone and together with
forth-core, undo-history, pretty-print, and pretty-print-extra; every pin
red under its named mutation; RAM and flash deltas in the commit; one audit
round on the stage's fixes.

| Stage | Content | Exit test |
|---|---|---|

| G2 | `LINE`, `BOX`, `RECT`, `ARC`, `CIRCLE`, `FCIRCL`, `TEXTOUT`, `DISP`, `GMODE`, `GCLIP`, with clipping. | Endpoint and clip-edge pins per command. Invert pin. Off-screen calls leave the buffer unchanged. Steps per second recorded. |

| G4 | `EYEPT`, `XVOL`, `YVOL`, `ZVOL`, `NUMX`, `NUMY`, `WIREFRAME`, `PT3D`, `LINE3D`. Flash of the float trig measured. | A known cube projects to known pixels. A plane draws a known mesh. One BMP hash oracle. Steps per second recorded. |

## 8. Risks

| Risk | Mitigation |
|---|---|
| Code paints over the canvas while a program runs: the status bar walk every 256 steps stays inside rows 0 to 19; the busy indicator and `VIEW` do not. | G1 lists every painter and pins each one. `VIEW` inside the view is refused or redirected. Stan decides in G1. |
| The softkey path bypasses the block, as it did for the browser in the pretty-print audit. | Carry the byte-identical `calcMode < 19` clause. Mode 21 is inside the range. Pin both paths. |
| Off-screen writes corrupt memory. `bitblt24` checks x only. `lcd_fill_rect` drops the whole call. | Every command clips first. Pins at all four edges. |
| The DMA refresh is not available on the simulator or behaves differently. | The simulator path uses the plain refresh. The cadence is the same. Both are pinned. |
| Flash growth from float trig. | Measured in G4. Fallback: a sine table. |
| The interpreter's fixed per-step cost hides the package's speed. | The baseline of G0 separates the two. The package reports its own cost. |

## 9. Rulings of the second round, 2026-09-04

1. The coordinate rule of section 4.3 is accepted: a long integer is a
   pixel, a real is a user coordinate through the window, and the default
   window is the pixel grid.
2. `FCIRCL` stays.
3. 3D lines use the current point: `PT3D` sets it, `LINE3D` draws from it
   and moves it.
4. `VIEW` and `AVIEW` do nothing in the canvas view. The program continues.
   The package adds `DISP n`: it draws the alpha register on line n of the
   canvas, from the top left. Precedent: RPL `DISP` (HP 50g AUR p. 3-60,
   verified).
5. Tests run on the simulator only. Stan does not run tests on the DM42.
   Hardware facts (the DMA refresh, real timing) are documented as untested.
   The G0 baseline is measured on the simulator.

## 10. Open points for Stan (closed)

1. Section 4.3: a long integer is a pixel, a real is a user coordinate
   through the window, and the default window is the pixel grid. Yes or no.
2. `FCIRCL`, the filled circle, has no HP precedent. Keep it, or leave it
   out of the first version.
3. 3D lines through a current point: `PT3D` sets the point, `LINE3D` draws
   from it and moves it. Without `LINE3D`, a program can draw surfaces
   only, and the G4 cube test needs lines. Accept this form, or use two 3
   by 1 vectors in Y and X instead.
4. `VIEW` and `AVIEW` inside the canvas view. Option A: they do nothing,
   and the program continues. Option B: they close the view and redraw the
   normal screen, and the drawing is lost. Option C: they write their text
   onto the canvas at a fixed position. Recommendation: option A.
