# HP graphics command conventions: research notes

Date: 2026-09-04. Two researchers read the HP manuals. Two skeptics then opened every cited source and confirmed or corrected each entry. Corrections are applied below. Sources are primary: the HP 50g and HP 48G Advanced User's References on hpcalc.org, the HP 50g User's Guide, the HP Prime User Guide on hp.com, the HP-42S Owner's Manual, and the Free42 and Plus42 pages on thomasokken.com.

Conventions, as reported:

HP Prime PPL (source: HP Prime Graphing Calculator User Guide, https://h10032.www1.hp.com/ctg/Manual/c05939731.pdf, chapter 29 'Programming in HP PPL', section 'Drawing', printed pages 637-645). The guide says there are 10 graphics variables G0-G9; G0 is always the current screen. Twenty-six functions modify them. Thirteen use Cartesian coordinates from the current app's Xmin, Xmax, Ymin, Ymax. The other thirteen carry a _P suffix and use pixel coordinates, where pixel 0,0 is the top-left pixel of the GROB and 320,240 is the bottom-right. So in _P form the origin is top-left and y grows downward. C→PX and PX→C convert between the two systems. Colors are given as #RRGGBB integers (the guide says 'in the same way as a color is specified in HTML') or with RGB(R,G,B,[A]). The guide is not consistent about alpha: PIXON says aaRRGGBB with 0 opaque and 255 transparent, BLIT and FILLPOLY say 0 transparent and 255 opaque, and RGB says a value over 128 flags the color transparent with no blending. I report each as written. Fill is a separate parameter where it exists: RECT has edgecolor and fillcolor, FILLPOLY and TRIANGLE take Color plus Alpha, ARC and LINE take one color. The guide also lists GROBW/GROBH, SUBGROB and DRAWMENU in the same section; I did not expand them.

HP-42S (source: HP-42S Owner's Manual, https://literature.hpcalc.org/community/hp42s-om-en.pdf, chapter 9 'Program Input and Output', pages 135-137, plus the Function Index). PIXEL takes the column from X (1 to 131, left to right) and the row from Y (1 to 16, top to bottom). The origin is pixel (1,1) at the top-left and y grows downward. A negative x draws a vertical line at column |x|; a negative y draws a horizontal line at row |y|; both negative draws both. PIXEL sets flags 50 and 51 so later PIXEL and AGRAPH calls add to the display. CLLCD blanks the whole display. AGRAPH puts the image's upper-left corner at column X, row Y; each Alpha character code is an 8-bit column pattern; flags 34 and 35 select OR, overwrite, clear-duplicates, or XOR. CLD 'clears a message from the display'; the OCR of page 26 lost the CLD label, so I cite the Function Index entry. The DM42 help page (https://technical.swissmicros.com/dm42/fat/HELP/dm42functs.htm) and the alternative Free42 manual (https://thomasokken.com/free42/doc/42s.pdf) repeat the same one-line descriptions; the DM42 page adds 'Negative values define lines.'

Free42 (source: https://thomasokken.com/free42/, section 'Free42 Extensions to the HP-42S Instruction Set'). Free42 adds no drawing command. Its only display-size additions are WIDTH and HEIGHT, which always return 131 and 16.

Plus42 (source: https://thomasokken.com/plus42/, sections 'Big Display', 'Function Plotting', 'The Plot Viewer', and the function summary; history at https://thomasokken.com/plus42/history.html). The display is resizable (default 8 rows by 22 columns, 131x64 pixels; rows 2-99, columns 22-999). WIDTH and HEIGHT return the pixel size so PIXEL and AGRAPH programs stay resolution-independent. The plotting commands are PGMPLOT, EQNPLOT, PARAM with XAXIS and YAXIS, CONST, VIEW with XMIN, XMAX, YMIN, YMAX and SCAN, and PLOT; the plot window is in user coordinates XMIN..XMAX by YMIN..YMAX. The page's function summary also names LINE, PLOT.M and VIEW.P under 'Function Plotting', and the history says LINE and PLOT.M were added to CATALOG->MISC, but neither page describes them. I found no primary-source description of LINE, PLOT.M or VIEW.P, so I report only their existence and give no semantics for PLOT.M and VIEW.P. The Plus42 page does not restate the PIXEL origin or the negative-coordinate rule; only the HP-42S manual documents those.

Not covered: the task did not ask for HP-48/49/50 RPL commands, so none are reported.

Conventions, as reported:

Sources. All commands come from two primary documents: the HP 50g/49g+/48gII Advanced User's Reference (https://literature.hpcalc.org/official/hp50g-aur-en.pdf, chapter 3; page numbers 3-nn are given per command) and the HP 48G Series Advanced User's Reference, edition 4 (https://literature.hpcalc.org/community/hp48g-aur-en.pdf, chapter 3, OCR text layer). The coordinate statements come from the HP 50g User's Guide (https://literature.hpcalc.org/official/hp50g-ug-en.pdf, chapter 22, pp. 22-19 to 22-25). The HP48 FAQ appendix B (https://www.hpcalc.org/hp48/docs/faq/48faq-10.html) confirms the 3D commands and ANIMATE as G/GX additions. The 50g AUR command index (appendix I, 'First' column) shows PIXON/PIXOFF/PIX?/LINE/TLINE/PVIEW/PDIM/PICT/PX→C/C→PX/GOR/GXOR/→GROB/XRNG/YRNG/FREEZE/ERASE/LABEL/REPL introduced on the 48SX, DRAW/DRAX/CLLCD/PMIN/PMAX/SUB on the 28C, LCD→/→LCD on the 28S, and all 3D commands, RES and PICTURE on the 48GX; so every command listed exists on the 48G, 49G/49g+ and 50g, except GROBADD (49 ROM 1.05 and later). I did not use the HP 48G Series User's Guide PDF because it has no text layer. Every requested command was found; none was left out. Two 48G AUR page numbers (AXES, PMAX) were unreadable in the OCR table of contents, so those entries cite the 50g AUR only.

Two coordinate kinds. Every drawing command that takes a position accepts either kind, but both arguments of one command must be the same kind (50g AUR stack tables). Pixel coordinates are a list of two binary integers { #n #m }: n is the column, m is the row (SUB example: { #10d #20d } { #20d #40d } gives Graphic 11 x 21). The origin { #0h #0h } is the top-left pixel of PICT/the screen and y increases downward; the bottom-right pixel of a 131×64 screen is { #82h #3Fh } (50g UG p. 22-25). PVIEW, →LCD, GOR, GXOR and REPL all place the top-left corner at the named pixel (50g AUR). User-unit coordinates are complex numbers (x,y). PPAR holds (xmin,ymin) as the lower-left corner and (xmax,ymax) as the upper-right corner of PICT (XRNG, YRNG, PMIN, PMAX entries), so user y increases upward; pixel { #0 #0 } corresponds to (xmin,ymax) and the bottom-right pixel to (xmax,ymin) (50g UG p. 22-25). The user origin is wherever XRNG/YRNG/PMIN/PMAX/CENTR put it; default x range is −6.5..6.5, default y range −3.1..3.2 (48gII) or −3.9..4.0 (50g/49g+). C→PX and PX→C convert between the kinds; PX→C returns the center of the pixel. The center pixel is row 32, column 65 on the 48G (131×64) and row 40, column 65 on the 50g/49g+ (131×80) (CENTR entries). ARC angles run counterclockwise in the user-unit orientation and use a constant pixel radius.

Naming. Grob commands use arrows in their names: →GROB, LCD→, →LCD, PX→C, C→PX (ASCII forms ->GROB, LCD->, ->LCD, PX->C, C->PX; the 50g UG prose spells the last two PXC and CPX). Plot-type commands (WIREFRAME etc.) take no stack arguments; they only write ptype into PPAR, and DRAW then reads EQ, PPAR and VPAR. VPAR is { xleft xright ynear yfar zlow zhigh xmin xmax ymin ymax xeye yeye zeye xstep ystep }; XVOL/YVOL/ZVOL, XXRNG/YYRNG, EYEPT and NUMX/NUMY set its parts, all in user units of the 3D volume, never pixels.

FREEZE argument. n is the sum of 1 (status area), 2 (stack/command-line area) and 4 (menu area); 3 = status + stack, 7 = all; values ≥ 7 or ≤ 0 act as 7; a graphics display survives only with 3 or 7 (50g AUR p. 3-91; 48G AUR p. 3-123).

Filled shapes. No filled-rectangle or filled-circle command exists in RPL: the 50g AUR command index and the 48G AUR table of contents contain no FILL command, BOX is documented only as a box from two corners, and ARC draws only the arc. The index has CIRC, but it is a CAS command in the ARITH PERM menu, and RECT is the rectangular-coordinate mode, not a drawing command. The documented way to fill a rectangle is #w #h BLANK NEG then REPL (or GOR) at a position (50g AUR REPL example 3, p. 3-199). The interactive Picture environment has a CIRCL soft key that draws a circle outline through the cursor (50g UG p. 12-45); it is a menu operation, not a programmable command. The Wikibooks drawing-commands page (https://en.wikibooks.org/wiki/Programming_HP_Calculators/Commands/Drawing_Commands) describes BOX as an outline, but it misstates FREEZE and ERASE, so I did not rely on it.
